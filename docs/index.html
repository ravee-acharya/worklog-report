Worklog Report for Jira

Pivot Jira worklogs by person, project or issue over any date range, drill into the individual entries behind any number, and export the detail — including worklog comments — to CSV.

Overview

Worklog Report turns Jira worklogs into a pivot table: one row per person (or project, issue type or issue) and one column per day, week or month. Every number is clickable, so you can always see the individual worklogs behind a total.

  • Pivot by period — day, week or month columns across any From/To range.
  • Group up to three levels — Categorize, Group by and 2nd Group, across User, Project, Issue Type and Issues.
  • Drill down anywhere — click a cell, a row total or the grand total row to list the worklogs behind it.
  • See the comments — worklog comments are shown in full, with bullet and numbered lists preserved.
  • Spot missing comments — values are shown in red where a worklog in that bucket has a blank comment.
  • Save filters — including rolling date ranges that follow the calendar.
  • Export to CSV — the pivot itself, or one row per worklog with its comment.

Runs on Atlassian. The app sends no data to any external service — everything stays inside Atlassian. It reads Jira as you, so you only ever see worklogs on issues you already have permission to view.

Getting started

  1. Ask a Jira administrator to install Worklog Report on your site from the Atlassian Marketplace.
  2. In Jira, open Apps in the main navigation and choose Worklog Report.
  3. Set From and To — both are required. The default is the 1st of the current month to today.
  4. Click View Report.

No configuration or admin setup is needed beyond installation. Every user gets their own saved filters and remembered settings.

Build a report

The toolbar has two rows. The first defines what the report covers; the second holds saved filters and the actions that run against it.

Scope (first row)

ControlWhat it does
ProjectsLimit the report to one or more projects. Leave empty for all projects you can see. Selecting projects also narrows the Users list to members of those projects.
UsersLimit the report to specific people. Leave empty for everyone.
From / ToThe reporting range. Both required. Ranges spanning several months are supported.
PeriodWhether each column is a Day, Week or Month. Day columns also show the weekday, and weekends are shaded.
CategorizeThe first grouping level — the left-most column of the report.
Group byAn optional second grouping level.
2nd GroupAn optional third grouping level.
Time UnitDecimal (1.50) or Hrs:Min (1:30).

Grouping dimensions are User, Project, Issue Type and Issues. Picking the same dimension twice has no effect — it is only shown once.

Actions (second row)

ControlWhat it does
Saved FiltersLoad a previously saved combination of filters. See Saved filters.
Save Filter / Delete FilterSave the current toolbar as a named preset, or delete the selected one.
JQLAn advanced override. When filled in, it replaces the Projects and Users filters, which are disabled while it is active.
Group TotalAdds a subtotal row per outer group when more than one grouping level is in use.
View ReportRuns the report.
Export CSV / Export CommentsSee Exports.

Reading the table

  • Each row ends with a Total for the whole range; the last row is a grand total across everyone.
  • Blue values are clickable — they open the worklogs behind that number.
  • Red values mean at least one worklog in that bucket has no comment.
  • - means no time was logged.
  • Click a column header with the ⇅ marker to sort by it.

Worklog details

Click any value in the report to open the worklogs behind it:

  • a date cell — that person's worklogs for that day, week or month;
  • a row's Total — all of that person's worklogs across the whole range;
  • a cell in the grand total row — everyone's worklogs for that column, or for the whole range.

Each entry shows the issue key (a link to the issue), issue summary, the worklog comment, time spent, the Worklog Date (the day the work was logged against) and the Worklog Created Date (when it was entered into Jira — often a different day).

Comments keep their original formatting, so bullet lists and numbered lists appear as the author wrote them.

Saved filters

Click Save Filter to store the current toolbar under a name. Saved filters are private to you.

When saving, choose how the preset should handle dates:

  • Fixed dates — always reports the exact From/To that were saved. Right for a closed period, such as a finished quarter.
  • Month to date, Last month, Week to date, Last week, Last 7 days, Last 30 days, Year to date — recalculated every time the preset is opened.

Tip: choose a rolling range for anything you run regularly. A preset saved as Month to date in November reports December when you open it in December; one saved as Fixed dates keeps reporting November, by design.

The dialog shows which dates your choice resolves to today, so you can confirm before saving. Delete Filter removes the selected preset after a confirmation — this cannot be undone.

Exports

Both exports produce CSV files, which open directly in Excel, Google Sheets, Numbers and any other spreadsheet tool.

Export CSV

The pivot table exactly as shown on screen — the same rows, date columns and totals.

Export Comments

One row per individual worklog, with a trailing total. Columns are: Author, Date Logged, Project, Issue Key, Issue Summary, Issue Type, Hours, Comment, Worklog Created Date.

Use this when you need the comment text itself — for client reporting, invoicing backup, or checking that work has been described properly.

Accented characters and symbols appear correctly in Excel: exports are written with a UTF-8 byte order mark so Excel decodes them properly rather than mangling dashes and apostrophes.

Before sharing an export, review it for confidential project detail and personal information, and follow your organisation's data-handling policies.

Permissions & data

  • Jira permissions are respected. The app queries Jira as the signed-in user, so people only see worklogs on issues they can already view. There is no way to use the report to see more than your Jira account allows.
  • Automation accounts are excluded. Worklogs created by app or bot accounts are left out, so totals reflect people.
  • No external data transfer. The app declares no outbound network access; all processing happens within Atlassian.
  • What is stored. Only your saved filter presets and your last-used Period setting, held per user within the Atlassian platform. Worklog data itself is never copied or retained.
  • Access requested. Read access to Jira work and user data, plus app storage for the presets above. The app makes no changes to your Jira data.

Troubleshooting

"Incomplete report" warning

This means Jira did not return worklogs for some issues — usually rate limiting on a large report. The totals shown are genuine but lower than reality. Narrow the date range or the project list, or run it again in a few minutes.

The report is empty

Check the date range first. Then confirm whether the JQL box has something in it — a JQL query overrides the Projects and Users filters entirely. Finally, confirm you have permission to view the issues in question.

A saved filter shows the wrong month

It was saved with Fixed dates. Load it, adjust the dates, and re-save it with a rolling range such as Month to date. See Saved filters.

The Users list looks short

The Users list is scoped to the projects you have selected. Clear the Projects filter to see everyone.

Numbers are red

That is deliberate: at least one worklog in that cell has no comment. Click the value to see which.

An export does not download

Confirm the report has results, then check your browser's download settings and any pop-up blocking. If it persists, contact support with the steps to reproduce.

Support

For help with Worklog Report, use the support contact shown on the app's Atlassian Marketplace listing.

When reporting a problem, please include: what you were trying to report on (date range, projects, users, period), what you expected versus what you saw, and the app version. Screenshots help.

Please do not send passwords, API tokens, or exported worklog data containing confidential information. A description of the problem is enough to begin.
